# Мастерская CRM

CRM для сервисных центров и ремонтных мастерских: приёмка и заказы, клиенты, склад запчастей, продажи, касса, отчёты и зарплата мастеров.

## Несколько мастерских в одной системе

Каждая мастерская регистрируется как отдельная **компания** (`/register`). У компании свои точки, сотрудники, клиенты, заказы, склад и касса.

Данные компаний разделены на трёх уровнях:

1. **Код.** Все запросы идут через `tenantDb(companyId)` (`src/lib/db.ts`), который сам добавляет фильтр `companyId` к каждому запросу и к каждой новой записи.
2. **База данных.** Связи между таблицами построены на составных ключах `(companyId, id)`, поэтому база не даст привязать заказ одной компании к клиенту, точке, мастеру или товару другой.
3. **Тесты.** `tests/tenant.test.ts` проверяет, что одна компания не может прочитать, изменить или удалить данные другой.

Внутри компании доступ зависит от роли: владелец и администратор видят всё, приёмщик работает с заказами, складом и кассой, мастер видит только свои заказы. Сотрудника можно закрепить за одной точкой.

## Возможности первой версии

- Приёмка: клиент (поиск по телефону), устройство с подсказками бренда и модели, IMEI, неисправность, комплектация, внешний вид, срок, предоплата.
- Настраиваемые статусы. Заказ нельзя выдать, пока он не оплачен полностью. Изменения в закрытом заказе запрещены.
- В заказ добавляются работы из прайса и запчасти со склада; запчасть автоматически списывается со склада точки.
- Полная история заказа: кто и что изменил.
- Печать квитанции о приёме, акта выдачи и наклейки с номером заказа.
- Публичная ссылка, по которой клиент видит статус своего заказа.
- Склад по точкам: приход со средней закупочной ценой, инвентаризация, минимальный остаток, история движений.
- Продажи без заказа: поиск по названию или штрихкоду.
- Касса: остаток наличных, приход и расход по статьям, операции за день.
- Отчёты: выручка, прибыль, заказы и зарплата мастеров в процентах от работ.
- Двухфакторный вход по коду из приложения-аутентификатора.
- Скупка техники: лента объявлений из групп ВКонтакте и Telegram-каналов, «Беру в работу», «Выкупил» (техника на склад, расход в кассу), рейтинг сотрудников по выкупу за месяц.

## Скупка техники

Раздел «Скупка» (`/buyback`) видят все сотрудники, источники настраивают владелец и администратор.

- **Источники** — ссылки на открытые группы ВК (`vk.com/…`) и публичные Telegram-каналы (`t.me/…`) с ключевыми и стоп-словами. Сервер проверяет каждый источник раз в 10 минут (`src/lib/collectors`, запускается из `src/instrumentation.ts`) и кладёт в ленту подходящие посты не старше 3 дней. Дубли отсекаются по ссылке. Объявления, которые никто не взял, удаляются через 30 дней.
- **Телефоны продавцов не собираются** (152-ФЗ): в ленте только текст поста и ссылка.
- **ВКонтакте** читается через официальный API, нужен сервисный ключ: vk.com/apps?act=manage → «Создать приложение» → тип «Standalone/Веб» → в настройках скопировать «Сервисный ключ доступа» и задать переменную `VK_SERVICE_TOKEN`. Telegram ключа не требует.
- **Выкуп** создаёт товар на складе текущей точки по цене выкупа и расход «Выкуп техники» в кассе. Прибыль в рейтинге появляется, когда этот товар продан через «Продажи».
- Авито и Юла (через прокси) и оценка цены — следующий этап.

## Волна 1: заказы как в привычных CRM для мастерских

- Главная: воронка заказов (новые, в работе, отложенные, готовые, выданные) с суммами, выручка за сегодня и за неделю, месяц или год с сравнением, просроченные и срочные заказы.
- Список заказов: вкладки по этапам с количеством, поиск, фильтры (статус, мастер, менеджер, тип заказа, срочные, просроченные, даты), выгрузка в Excel (CSV).
- Карточка заказа: вкладки «Информация» и «Работы и материалы», тип заказа, срочность, цвет, менеджер, крайний срок со временем, комментарий приёмщика, вердикт для клиента, скидка в % и ₽, гарантия на каждую позицию, фото и файлы, кнопки WhatsApp и Telegram, выдача с доплатой в один клик.
- Справочники (Настройки → Справочники): типы заказа и устройств, марки, модели, цвета, неисправности, комплектация, внешний вид. Новые значения запоминаются сами при приёмке.
- Печать нескольких документов сразу: квитанция, акт выполненных работ, гарантийный талон, отказной лист, товарный чек, наклейка.
- Тёмная и светлая тема (переключатель внизу меню).
- Часовой пояс задаётся переменной `TZ` в `.env` (по умолчанию `Asia/Yekaterinburg`).

## Волна 2: склад и продажи

- Склад: дерево групп товаров, поставщики, цены розничная, ремонтная (подставляется в заказ) и минимальная (ниже продать нельзя), фильтры «в наличии / заканчиваются / нет / архив», выгрузка в Excel.
- Складские документы: оприходование от поставщика с пересчётом средней закупочной, перемещение между точками, списание, инвентаризация. Каждый документ проводится целиком или не проводится вовсе.
- Касса продаж: список товаров с поиском и сканером штрихкодов, чек с клиентом и скидкой, проверка минимальной цены, товарный чек, история продаж, возврат части или всего чека.
- Кассовая смена: открытие, итоги по продажам, возвратам и оплатам заказов, закрытие с пересчётом наличных (недостача или излишек записывается в кассу).
- Загрузка товаров с остатками и клиентов из Excel (.xlsx) или CSV с проверкой перед загрузкой. Повторная загрузка не создаёт дубли.

## Запуск для разработки

Нужны Node.js 22 и PostgreSQL 16.

```bash
cp .env.example .env        # укажите DATABASE_URL
npm install
npx prisma migrate deploy   # создаёт таблицы
npm run dev                 # http://localhost:3000
```

Тесты используют отдельную базу `crm_test`:

```bash
npm test
```

## Запуск на сервере

```bash
DB_PASSWORD=надёжный-пароль docker compose up -d --build
```

Приложение откроется на порту 3000; перед ним ставится nginx с HTTPS. Для соответствия 152-ФЗ сервер должен находиться в России. Настройте ежедневный бэкап базы (`pg_dump`).

## Стек

Next.js 15 (App Router, server actions), TypeScript, Tailwind CSS, Prisma 6, PostgreSQL.

Суммы хранятся в копейках (`Int`), для перевода есть помощники в `src/lib/money.ts`.
